# Preflight — 1.10.0

PR: #375
Status: passed
Signed: 2026-09-04 against 67609ea

Four independent changes: driver tax as a decimal, work-tracker line item
quantity as a decimal, a currency filter on the weekly driver list, and
Quotes & Bookings filters round-tripping through the URL. The first two follow
the same pattern (a new `_dec`/`_decimal` column, a deprecated integer mirror
kept in sync by a Postgres trigger for the driver mobile app) and both are
covered by psql tests for the trigger and back-fill, plus unit tests for the
input-sanitizing logic. No RLS policy changed and no permission changed — see
the note at the end.

## New in this release

- [x] **Manage Team →** a driver **→ Driver section.** Type `14.975` into the
      tax rate field. It stays `14.975` (not rounded to `15`), and the payout
      preview line below updates to match.
- [x] **Work Trackers →** open a work tracker **→ Line Items tab.** Add a line
      with quantity `2.5`. The line total is `2.5 × unit amount`, and reopening
      the tab still shows `2.5`, not `2` or `3`.
- [x] **Work Trackers →** a week's page. Use the new **Currency** dropdown next
      to "See All Drivers" — pick **CAD**, then **USD**. Each shows only
      drivers paid in that currency; "All Currencies" brings everyone back.
- [x] **Quotes & Bookings.** Set a filter (e.g. a Sales Office) and type
      something into search, then click into a quote and press the browser's
      **back** button. The list still shows your filter and search text — not a
      blank list.

## Could have broken

- [x] **QBO bill total match.** On a work tracker group for a driver with a
      non-whole tax rate (e.g. Quebec), open the group modal and check the
      "totals match QuickBooks" indicator still agrees — this math now reads
      `taxDec` instead of the old whole-percent `tax`.
- [x] **Existing whole-percent tax rates.** Open a driver who already had a tax
      rate before this release (e.g. `13`). It should still read `13`, not
      `0` or blank, confirming the back-fill migration ran correctly.
- [x] **Existing whole-unit line item quantities.** Open a work tracker created
      before this release. Its line item quantities should still show their
      original whole numbers, not `1` (the new column's default).
- [x] Quotes & Bookings: with **Show Deleted** checked and a filter set, refresh
      the page from the address bar (not just navigating within the app). Both
      the filter and Show Deleted survive the hard reload.

## Not testing

- **The sync trigger keeping `tax`/`tax_dec` and `quantity`/`qty_decimal`
  consistent** — covered by `supabase/tests/driver_tax_dec.test.sql` and
  `supabase/tests/work_tracker_line_item_qty_decimal.test.sql`, which exercise
  insert/update from both sides.
- **Percent/quantity field typing (partial input like "14.", comma decimals,
  clamping)** — covered by `InputPercents.test.ts` and `quantityInput.test.ts`.
- **URL filter round-trip logic itself** (which params map to which filters,
  scorecard params merging alongside) — covered by `filterUrlSync.test.ts`.
- **The deprecated `tax`/`quantity` columns being read correctly by the driver
  mobile app** — that's a separate codebase (`br_driver`), unreachable from
  here.
- **Whether a driver over 100% tax or a negative quantity can be entered** —
  both fields clamp/reject in the sanitizer and the DB has a `>= 0` check for
  quantity; already covered by the unit tests above, not worth re-checking by
  hand.

## Permissions

No entries in `permissionPageData.ts` needed changing. Checked against
`pg_policies` for both tables touched:

- **Driver tax rate** — no RLS policy changed in this PR. `drivers_update`
  already restricts writes to admins and the driver's own account manager
  (by ownership or shared zone); that's exactly what the existing "Edit Team
  Members" entry describes, and typing a decimal instead of a whole number
  doesn't change who can do it.
- **Line item quantity** — no RLS policy changed. `work_tracker_line_items_update`
  already allows admin/account_manager on any row, and a driver only on rows for
  their own work tracker; this is covered by the existing "Work Trackers" entry.
- **Currency filter and URL-persisted list filters** — both are client-side
  narrowing of data the viewer could already see; they don't expose or restrict
  anything new.

One pre-existing mismatch noticed while checking the Work Trackers RLS, **not
caused by this PR**: `work_tracker_line_items_update` lets a driver update line
items on their own work tracker, but the "Work Trackers" entry in
`permissionPageData.ts` says drivers "cannot delete a work tracker or change any
other information" beyond status and inspection forms. Worth a decision on
which one is actually intended, but it's unrelated to this release — flagging
rather than fixing here.
