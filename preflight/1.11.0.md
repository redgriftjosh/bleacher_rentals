## New in this release

- [x] **Pickup/dropoff time — Exact.** Open a Trip's work tracker, set Pickup
      Time to **Exact**, pick 8:00 AM, save, reload the page, reopen the
      tracker — it still shows Exact / 8:00 AM, and the trip list's Time
      column reads "8:00 AM".
- [x] **Pickup/dropoff time — Any Time.** On a tracker that has never had a
      time set, the Time column on the trip list and the picker in the modal
      both read "Any Time" (not blank). Switch it to Any Time explicitly, save,
      reload — same result.
- [x] **Work tracker Type picker.** Open a work tracker, change Type from Trip
      to Repair/Maintenance — the Pickup section disappears and a single
      generic field set (with both Setup and Teardown Required) takes its
      place. Switch back to Trip — the split Pickup/Dropoff layout returns.
- [x] **Work Tracker Types admin page.** As an admin, Configuration → Work
      Tracker Types shows exactly 3 types, each with a QuickBooks account
      dropdown per connection. Change one, save, reload — it stuck. There is
      no add/rename/delete control anywhere on the page.
- [x] **Bill of Lading PDF for a non-Trip type.** Generate a BoL for a Repair/
      Maintenance tracker — one "SHIPMENT INFORMATION" panel with Date, Time,
      Address, POC, Instructions, and both Setup/Teardown Required, not a
      blank Pickup panel.
- [x] **Drive Time / Mileage columns.** On a driver's week page and in the
      downloaded PDF, every trip row shows a drive time ("2.4 hrs") and
      mileage ("21.4 mi (34.4 km)"), and the SubTotal row totals both.

## Could have broken

- [x] **Address autocomplete, anywhere in the app.** Type an address into the
      autocomplete on a Company/Contact and on a work tracker's pickup
      address — suggestions appear, and picking one fills the actual street/
      city/state, not the raw suggestion text. This component was rewritten
      (geocodes by place_id now) and is shared by 8 different features.
- [x] **Google Maps loads on first page view.** Sign in fresh (or hard-reload)
      on a page with an address field — the map script (now loaded
      `afterInteractive` instead of `beforeInteractive`) isn't late enough to
      leave the field silently non-functional.
- [x] **Driver mileage/pay on a trip with real addresses.** Open a work
      tracker with pickup and dropoff addresses set — the distance/duration
      (and the driver pay it feeds) shows a real number, not blank or an
      error. The `/api/distance` waypoint building changed.
- [x] **Editing only the pickup/dropoff time on an accepted trip triggers the
      driver notification / un-accept flow.** This was a live bug fixed in
      this PR (change-detection never compared the time fields). Change just
      the pickup time on an accepted trip and save — it un-accepts and the
      driver gets notified, same as changing any other field would.

## Permission changes in this release

One new entry in `permissionPageData.ts`: **Work Tracker Types** — admin can
assign QBO accounts to the 3 fixed types; account manager, developer, and
viewer all get `none`. Backed by `accessConfig.ts` (`/work-tracker-types` in
admin's `allowedRoutes` only) and the new
`workTrackerTypesAccess.am.spec.ts`, which asserts an account manager is
redirected out.

**Database now matches, per your instruction.** `pg_policies` on
`WorkTrackerTypes` and `WorkTrackerTypeQboAccounts` used to let
`account_manager` `INSERT`/`UPDATE`/`DELETE` directly — pre-existing, and
previously correct (the old "Edit types" link was open to any account
manager). New migration
`20260909140000_work_tracker_types_admin_only_writes.sql` narrows both
tables' write policies (`rbac_insert`/`rbac_update`/`rbac_delete`) to `admin`
only. `rbac_select` is untouched — still `admin`+`account_manager` on both,
because an account manager still needs to read `WorkTrackerTypes` for the
Type dropdown on any work tracker, and `WorkTrackerTypeQboAccounts` from
`/api/quickbooks/create-bill` (`ReadyForPaymentButton`/`CreateBillModal`,
which any account manager can trigger — not admin-gated). Verified against
`pg_policies` after a local `db reset`; `tc`/`vitest`/pgTAP all still pass.
